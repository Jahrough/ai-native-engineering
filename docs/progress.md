# Progress tracking framework

This framework supports honest, evidence-based progress reporting. It does not record learner results on their behalf. Keep an individual log wherever appropriate; do not commit personal, sensitive, customer, or secret data to this repository.

## Status vocabulary

Use one status per competency or phase:

- **Not started** — no work attempted.
- **In progress** — practice is underway; evidence is incomplete.
- **Evidence ready** — candidate evidence exists and awaits independent review.
- **Demonstrated** — evidence meets the [assessment criteria](evaluation.md), including verification.
- **Revisit** — review found a gap or the skill has not been maintained.

Reading, watching a tutorial, or receiving a correct answer from an AI system is learning activity, not competency evidence.

## Suggested learning log

For each meaningful work session, record:

| Field | What to capture |
|---|---|
| Date and phase | Date, phase, and competency practiced |
| Objective | The concrete question, task, or outcome |
| Practice | Exercise or implementation performed; environment and constraints |
| Evidence | Link or reference to artifact, tests, experiment, review, or observation |
| Verification | How the result was checked independently; who reviewed it if applicable |
| Outcome | Observed result, measures, limitations, and unexpected behavior |
| Reflection | What changed in understanding; remaining uncertainty or risk |
| Next action | One specific follow-up or reason to advance/revisit |

Do not include credentials, private prompts containing sensitive data, unapproved source material, or raw user/customer data. Link to authorized artifacts instead.

## Phase review

At the end of each phase:

1. Re-read its stated outcomes and evaluation criteria.
2. Assemble evidence for each outcome and identify evidence that is missing or weak.
3. Reproduce key results without relying on the original AI response where feasible.
4. Request an independent review appropriate to the risk and context.
5. Record status, confidence, feedback, and next actions; explain any test-out using equivalent evidence.
6. Advance only when the [readiness criteria](progression.md) are met. Otherwise, practice and reassess.

## Reassessment and maintenance

Repeat the baseline periodically and after substantial role or technology changes. Revisit advanced skills when tools, model behavior, threat conditions, or system architecture change. Track dated evidence rather than claiming permanent mastery. The six-month schedule is adjustable; completion is not inferred from elapsed time.
